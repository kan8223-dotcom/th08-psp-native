## Changes since the previous public r156

- ME worker paths for selected bullets, effects, background and popup work; audio remains on SC.
- Streamed GE command lists, direct/batched primitives, triple buffering, reusable HUD front vertices and batched HUD text.
- Bounded exit recovery and replay-surface recovery; this is not a claim that every possible hang is eliminated.
- Logging disabled: no new BOOT/performance/SDL/PSPGL trace files. Ordinary game save/replay I/O and startup extraction of the embedded ME bridge remain enabled.
- r237: reuse one bounded coverage mask across the five passes of outlined text. It does not cache all future dialogue.
- r238: prefer lower eDRAM for eligible fresh stage-boss portrait uploads only when at least 256 KiB headroom remains. Fallback to Main RAM; no eviction, live migration or new VRAM pool. Existing texture packing and geometry are retained.
- Automatic draw cadence (60/30/20) with manual SELECT override; bombs use 20 draws/s in automatic mode. Simulation targets 60 Hz; this is not a constant 60-rendered-FPS promise.

## Validation and remaining limitations

- Exact installed PBP: device readback matched before this publication. Player reports substantial overall improvement, but dialogue fast-forward still feels heavy.
- The no-log r236 predecessor has a reported replay completion at 423 MHz on PSP Go/M2, and a freeze at 443 MHz. Logged r235 also had successful 443 MHz runs. Different builds/logging states must not be treated as a controlled clock-only comparison or proof that r238 is universally stable.
- Current r238 full-run completion, other PSP models and exact FPS gains are not established by those earlier results.
- Host checks for text coverage and portrait uploads covered OFF/ON pixel equivalence, memory bounds and failure fallback with ASan/UBSan. These checks are not GE hardware timing measurements.
- The publication checkout was built clean. Preserving the historical bootstrap label as described below also reproduced the installed PBP byte-for-byte with the installed toolchain. Reproducibility across other toolchain versions is not promised.
- Internal-storage stalls, heavy dialogue, unsupported Last Word practice and lack of PSP-1000 support remain.

## Build

Use a clean checkout with PSPDEV/PSPSDK, PSP SDL2/image/ttf, CMake, Python 3 and xxd installed:

```sh
bash tools/build_r238_nolog_20260909_183252.sh
```

The complete feature vector is in that script. It does not depend on private build histories or original game files.
The installed incremental build retained `psp/video.o`'s r236 bootstrap/error-screen label. The small companion Make fragment preserves just that label for exact release reconstruction; the product code and other build IDs are r238. The PBP hash above is the authoritative identifier, not that fallback screen label.

## Pthreads source and rebuilding

The statically linked pthread-embedded library is LGPL; its full corresponding upstream source is attached as `PTHREADS_SOURCE_4f43d30_20260909_183252.tar.gz`.
The installed PSPSDK build record identifies [pspdev/pthread-embedded commit 4f43d30a23e8ac6d0334aef64272b4052b5bb7c2](https://github.com/pspdev/pthread-embedded/tree/4f43d30a23e8ac6d0334aef64272b4052b5bb7c2); its public headers match the installed library headers.
The application source and build files are in this release's Git tag. You may modify/rebuild the library and relink the application; no restriction on debugging such modifications is imposed by this port.

With your own PSPSDK installation, unpack that source archive, build it with `make -C platform/psp`, and install it with `make -C platform/psp install` before running the game's clean-checkout build script. Alternatively, use the source to provide your own replacement `libpthread.a` on the linker search path.
The toolchain used here records newlib `9e0a073634ad73e8e088f2e071c55a9fe5d39709`, GCC `989408bfa4b9125395df79219228df3d809df66c`, and PSPSDK `800ce356bbe5ac884d87837e7553dfd5f70e4401`; PSP SDL2/image/ttf report 2.32.8 / 2.8.6 / 2.24.0.
